# CCode Windows 分发包

## 0.0.7 启动总控集成

本版本从当前源码构建 Windows x64 预览包，默认总控执行遵循 `ccode-startup-global-prompt.md`。CLI 能力声明的私有协议版本升级为 2，旧版 1 不视为支持启动配置，避免混装旧 Agent。安装包不内置总控正文；构建产物与真实中台/模型验收分别记录，不自动发布或部署。

## 目标

产出 Windows x64 安装包，可与原版 ZCode 并存，通过中台登录和私有内存通道使用总控派单。模型通过现有自定义供应商入口配置；不接 sub2api，不内置个人凭据或核心 Skill 正文。

## 所有者与边界

- CCode 首次对外发布为 `v0.0.1 预览版`。根 package.json 的 `ccodeRelease` 管理产品版本及渠道；安装器、主程序 PE 版本、app.asar/package.json 与官网使用 `0.0.1`。根 version 与现有 buildMetadata.appVersion 继续作为上游运行时/远程资源兼容标识，不随产品发布号降级。
- 本次修正复用已经发布的应用内容，仅在独立副本更新产品元数据并重新生成安装器，避免混入工作区其他未发布功能。保持原 CCode appId、安装目录、数据目录和协议注册。

- Desktop 构建身份负责 CCode 名称、独立 appId 和安装路径；早期启动负责独立数据目录，开发环境显式覆盖仍有效。
- 安装包使用独立 ESM 启动文件，在动态加载 main 及其分包前设置环境和读取本实例设置；仅在 TypeScript 中前置 import 无法保证分包求值顺序。
- 总控派单唯一来源为中台知识库“总控skills”；CLI bundled-skills 仅保留普通技能，禁止分发核心正文及本地兜底。完整协议见 ccode-confidential-controller.md。
- Desktop 系统上下文负责按意图触发技能。明确执行、制作、修改、排查、继续已开始任务时先加载；问候、闲聊、概念讨论不加载。
- 总控版本由中台签发并按任务固定；本机只保留应用生命周期内存副本。历史业务数据、固定本机路径/端口、历史授权不随包发布；依赖技能和 CLI 需实际存在。
- 关闭上游自动更新和可选遥测，不让安装包更新回原版。更新通过后续重新打包安装完成。

## 验收场景

### 中台总控集成预览包

- 本次包含中台账户、动态总控、运行版本绑定及当前工作树功能的集成包使用 `v0.0.3 预览版`，不覆盖仅更改下载源的 v0.0.2 发行身份。
- 先完成 `prepare:runtime-assets` 再构建安装包；单独暂存 Agent bundle 会清理 glm 目录，不能代替插件及原生依赖的完整准备。
- 产物仅供本次集成验收，真实账户登录和受保护任务链尚未验收前，不宣称生产交付完成。

### 远程组件下载源

- `v0.0.2 预览版` 在已发布 v0.0.1 内容上仅更新产品版本元数据和远程组件下载源模块，独立重打包；不包含工作区其他未发布修改。OSS 使用新版本路径，保留旧安装包以便回退。

- CCode 面向国内用户，远程运行组件默认只使用 `https://cdn.codegeex.cn/zcode/electron/releases`，不再按语言或时区选择海外源，也不设置海外回退源。
- 保留内部运行时版本路径、显式自定义源、构建期源配置及测试环境源，便于后续迁移到自有 OSS；当前本地 `.env.production` 未配置 CDN_DOMAIN，使用国内默认源。
- 验收：中文、英文以及国内、海外时区的生产默认解析结果均只有国内源；测试环境与显式覆盖行为保持兼容。本次规则只涉及远程组件下载源。

1. 产物名称 CCode、独立安装身份，资源内不含总控派单 SKILL.md 或其他核心正文副本。
2. 包内不包含个人 API Key、OAuth 文件、用户会话或本机 AGENTS.md。
3. 新用户可使用现有模型配置入口；未配置时不宣称已可调用模型。
4. 任务请求先经中台授权启用总控；缺少通道或授权时不得回退本地。闲聊不加载总控。不承诺提示词具有不可绕过的安全边界。
5. 构建通过静态类型、lint、架构及打包资源检查；未运行交互/模型测试需明确披露。

## 2026-10-21 并存修复

- CCode 的操作系统 URL handler、运行时解析、开发启动声明、工作区打开与分享导入链接统一为 `ccode://`，不注册或兼容接管 `zcode://`。
- OAuth 客户端的回调及官网中转 redirect 参数使用 `ccode://oauth/callback`。上游 OAuth 应用标识不改名；上游是否允许此回调需要供应商确认，不以客户端构建通过声称官方登录可用。自定义模型供应商不依赖此回调。
- Windows 日志改为 `CCode-installer.log` / `CCode-uninstaller.log`，所有权清单为 `.ccode-install-manifest`。旧品牌版升级由旧卸载器使用旧清单；缺少新清单时沿用保留文件策略，不猜测官方文件归属。
- 所有 Windows 安装包都生成清单，不依赖可选 Computer Use helper 是否随包存在。
- macOS Finder 工作流及开发 app 标识、Linux desktop entry 使用 CCode 名称与独立标识。
- 保留内部 workspace 包名、协议字段及品牌根目录下的 `.zcode` 存储结构；这些不是系统全局名称，不做破坏性数据迁移。
- 本机旧 `zcode` handler 若仍指向本项目源码，备份该键后恢复到已存在的官方 `F:/zcode/ZCode.exe`；新的 CCode 启动仅注册 `ccode`。

事件顺序：安装/启动 CCode → 注册 ccode handler → 浏览器或分享链接触发 ccode → CCode 校验 host/path/state → 转发到对应窗口。官方 zcode handler 独立。
