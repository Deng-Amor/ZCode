# CCode 产品需求文档（PRD）

- 版本：v1.1
- 状态：已评审（2026-10-23 用户通过；§2 目标 5 与 §4.6 按 2026-10-22 三层架构拍板修订，见 §4.6 修订注）
- 范围：截至 2026-10-22 本轮“任务续接故障修复”讨论之前已确定的产品方向
- 不在范围内：`Confidential controller: EXECUTION_FAILED`、五分钟授权失败、内存/续接故障的根因分析与修复方案

## 1. 产品定位

CCode 是川升AI面向企业任务执行场景的桌面 AI 助手。它以本地客户端作为用户的工作入口，支持模型对话、项目任务、工具调用、MCP 能力和任务协作；数据中台提供需要集中发布、校验或依赖企业数据的能力。

产品应以 **CCode** 对外呈现，不再向用户暴露 ZCode 品牌、配置目录、更新源、版权名称或身份文案。模型供应商名称只在用户明确询问底层模型时按实际配置说明。

## 2. 目标与成功标准

1. 用户安装、启动、登录、升级和使用 CCode 时，不会误进入或依赖 ZCode 的产品数据、更新源或视觉身份。
2. 客户端能从 CCode 自有更新服务发现、下载并安装新版本；更新失败不影响现有版本继续使用。
3. 用户登录一次后，在安全存储可用的桌面环境中重启客户端可恢复登录，不反复要求输入账号密码。
4. 用户可导入已有 ZCode 项目与可迁移的会话历史，并明确查看导入结果与不可导入项。
5. 总控专家成为 CCode 的任务分派与执行治理入口：它能根据任务决定本地能力、MCP、企业数据中台和后续专业专家的调用顺序；总控正文以本地锁定 Skill 形态持有（非普通本地 Skill，不可浏览、导出或覆盖原件），更新走数据中台签名推送。
6. 对必须依赖企业真实数据、内部 API 或 MCP 执行的步骤，客户端必须实际调用对应能力，不能以提示词模拟成功。

## 3. 用户与场景

| 用户                | 场景                                 | 期望结果                                                          |
| ------------------- | ------------------------------------ | ----------------------------------------------------------------- |
| 企业员工            | 首次安装及升级 CCode                 | 看见 CCode 品牌，使用 CCode 更新地址，数据目录彼此隔离            |
| 已登录员工          | 重启或升级后继续使用                 | 在有效登录态下自动恢复账号，必要时只提示重试而不是误判登出        |
| 从 ZCode 迁移的员工 | 导入项目、会话与工作目录             | 可选择导入范围，原数据不被删除，导入结果可核对                    |
| 任务执行者          | 图像采集、上传、数据查询、交付等任务 | 总控专家识别必须调用的 MCP/内部能力并安排执行，不用文字假装已完成 |
| 管理员 / 发布者     | 发布版本、管理总控内容               | 通过数据中台发布受控版本，客户端只消费已发布版本                  |

## 4. 核心需求

### 4.1 品牌、版权与开源声明

- 桌面应用名称、窗口标题、启动页、图标、关于页、安装包、更新提示和产品自我介绍统一使用 CCode 与川升AI。
- 用户可见版权文本不得继续显示 ZCode。
- 产品保留 Apache License 2.0 声明；版权、许可证和第三方声明应放在关于页或安装目录的常规法律信息入口，不干扰主使用流程。
- 开源上游依赖的必要 notices 必须保留，不能通过改名删除。

### 4.2 CCode 私有数据目录与配置迁移

- CCode 使用独立于 ZCode 的应用数据根目录，至少隔离：账户凭据、会话索引、项目索引、设置、日志、插件与更新元数据。
- 新安装不得读取或覆盖 ZCode 的默认配置目录。
- 升级已有 CCode 版本时，按 CCode 自身目录完成平滑迁移。
- 需要导入 ZCode 数据时，只能通过用户触发的导入流程读取；导入默认复制，不能删除或迁移走原始 ZCode 数据。
- 导入完成后生成清晰的结果：成功项目/会话数、跳过原因、需人工处理的内容。

### 4.3 登录态恢复

- 桌面端登录成功后，使用操作系统提供的安全存储保存刷新凭据及必要账号标识；不得保存明文密码或访问令牌。
- 客户端启动时自动尝试恢复登录。
- 网络暂时不可用、服务端暂时异常、限流或超时时，保留已保存凭据并显示“账号暂不可用，可重试”；不能直接清除登录态。
- 明确拒绝、账号撤销、凭据损坏或来源不匹配时，清除失效凭据并进入登录页。
- 账号切换或退出后，旧账号关联的本地会话与权限上下文必须隔离。

### 4.4 自有在线更新

- CCode 使用独立的发布清单、下载域名、安装包名称、更新通道与版本号，不复用 ZCode 的更新地址或产品配置。
- 客户端启动后按策略检查更新；发现新版本时显示版本、摘要、下载/安装状态和失败原因。
- 更新包需校验版本、来源和完整性；下载或安装失败必须保留当前可运行版本。
- 预览版与正式版必须使用明确不同的更新通道。用户安装预览版时，不能误以为自己在订阅正式版更新。
- 更新完成后保留会话、账户恢复凭据、项目索引和用户设置。

### 4.5 ZCode 项目与历史导入

- 提供“从 ZCode 导入”入口，支持选择：项目、会话历史、收藏/置顶、工作目录映射和模型配置。
- 导入前展示来源路径、预计数量、重复项处理策略及不支持的数据类型。
- 会话导入保留原始时间、标题、消息与附件引用；无法访问的附件要显示缺失状态，不阻断其他会话。
- 同一来源重复导入应能识别已导入内容，避免生成重复任务。
- 用户可选择只导入项目、不导入会话，或反向选择。

### 4.6 总控专家

> **修订注（2026-10-23，v1.1）**：本节按 2026-10-22 三层架构拍板修订（原 v1.0 按”仅内存消费+启动全局提示词”口径表述）；规格以 `docs/specs/ccode-controller-local-skill.md`、`docs/specs/ccode-expert-skills-distribution.md` 为准。

总控专家是 CCode 的任务治理专家，不是用户可编辑或可导出的普通本地 Skill。Skill 体系分三层：

- **总控 skill（通用派发）**：本地内置锁定 skill——首次登录后从中台获取并经 Ed25519 验签落地为本地加密锁定副本（加密定位为防君子门槛，不是保密措施）；更新走中台签名推送，验签后原子落地、可回滚；用户不可修改锁定原件，只可开分支迭代；触发为”小 stub 常驻意图判定 + 完整 skill 命中加载”两层。
- **专家 skill（领域知识）**：唯一存于数据中台、按需下发——命中领域才加载、未命中零请求；下发内容经验签后本地缓存，用户只读不可改。
- **用户自有 skill**：用户自由修改；内容按企业回流策略每日自动上传中台（提供退出标记），经中台过滤策展后可发布回流共享。

不变条款：

- 总控专家负责判断任务目标、拆解步骤、分派专业专家、决定本地工具/MCP/企业数据中台的必要调用，并维护任务证据与台账要求。
- 对需要真实执行的步骤，必须调用相应 MCP、内部封装方法或数据中台接口。例如页面采集后上传图片，必须实际调用上传能力，不能只输出”已上传”。
- 总控发布版本由数据中台审核，客户端只消费已发布版本，不得自签或修改信任根；用户不能从普通 Skill 浏览、导出或覆盖锁定原件。
- 产品保留版本、来源和适用范围等可审计元数据；锁定正文不进入普通聊天记录、日志或导出内容。
- 每个版本可按发布策略补充一部分由数据中台提供的内容；抽取比例、内容边界、失败策略和版本固定方式由中台发布策略定义。
- 普通聊天、任务执行、工作流和子任务对总控的适用范围由产品策略明确，不能依赖模型自行猜测是否应启用。

### 4.7 台账、证据与关闭任务

- 任务台账必须记录来源、任务目标、执行步骤、调用的工具/MCP/数据中台能力、产物位置、关键证据、状态和关闭结论。
- 台账来源不清、关键证据缺失或必须调用的能力未执行时，任务不能标记为已完成。
- Skill 发布、台账写入和验收关闭应经过统一代码校验，而不是仅依赖提示词约束。
- 校验规则应支持自动化压力测试与回归验证；测试轮次、环境、输入样本、失败记录和结论可追溯。

## 5. 非功能要求

- Windows、macOS、Linux 的产品身份、数据隔离和更新行为保持一致；平台安全存储不可用时不得退回明文保存。
- 不记录密码、访问令牌、总控正文、企业敏感数据或私有接口响应到普通日志、会话导出或遥测中。
- 中台不可用时，涉及企业真实数据或必须调用的能力必须明确失败原因，不能生成虚假的完成结论。
- 所有远程交互应有明确超时、重试和可观察状态；用户能区分“等待中”“需要登录”“需要权限”“执行失败”和“已完成”。

## 6. 不在本期范围

- 当前任务续接失败、五分钟授权失败及 `Confidential controller: EXECUTION_FAILED` 的修复细节。
- 将 CCode 的所有本地能力迁移至数据中台执行。
- 为任意第三方模型服务提供绝对的总控内容保密保证。
- 直接删除、改写或接管用户原有的 ZCode 数据目录。

## 7. 验收场景

1. 新用户安装 CCode 后，关于页、启动页、安装包和更新提示只出现 CCode/川升AI，许可证入口包含 Apache-2.0 及必要第三方 notices。
2. 已登录用户关闭并重启 CCode，网络正常时自动恢复登录；网络暂时故障时保留凭据并提供重试。
3. CCode 检查到自有更新服务的新稳定版，完成下载和安装后仍保留账户、项目和会话。
4. 安装 CCode 不会创建、修改或读取 ZCode 默认数据目录；用户主动导入后，ZCode 原数据仍完整可用。
5. 用户导入项目和会话后，重复导入不会制造重复记录；缺失附件能被标识。
6. 用户发起“采集页面并上传图片”任务时，执行记录可证明采集、上传及必要的数据中台/MCP 调用真实发生；缺少上传调用不得标为完成。
7. 总控专家版本、来源、适用范围和关键调用证据可在台账中追溯；普通聊天导出不包含受控正文。
